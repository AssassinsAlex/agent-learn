# DeepSeek Harness 整体架构

## 一、架构核心

DeepSeek Harness 没有一个需要不断修改的“大核心”。它把能力拆成 Cordis plugin：插件向共享 runtime context 注册 service、typed event 和 effect；卸载插件时，注册会按 Cordis 生命周期撤销。

```text
Profile
  -> ordered bundles
    -> profile cordis.patch.yml
      -> home patch
        -> command-line patch
          -> Cordis plugin tree
```

`dsh-base` 通常提供模型、工具、Session、持久化、沙箱、审批、凭据和 telemetry；`dsh-web-app` 或 `dsh-headless` 在其上增加产品入口。

## 二、核心服务地图

| 能力 | 主要包 | runtime key |
| --- | --- | --- |
| Session Log 和内存 Session | `packages/core/session` | `ctx.sessions` |
| System Prompt 与工具 schema | `packages/core/system-prompt` | `ctx.systemPrompt` |
| Tool registry 和执行流水线 | `packages/core/tools` | `ctx.tools` |
| Agent registry、Agent 类型和事件 | `packages/core/agent` | `ctx.agents` |
| 默认 Agent driver | `packages/core/agent-loop` | `ctx.agentLoop` |
| LLM message/stream/adapter seam | `packages/llm/llm` | `ctx.llm` |
| Token pressure measurement | `packages/llm/token-meter` | `ctx.tokenMeter` |
| Context compaction seam | `packages/compaction/compaction` | `ctx.compaction` |
| Basic compaction provider | `packages/compaction/compaction-basic` | 注册 `ctx.compaction` |
| Tool result pruning | `packages/compaction/compaction-tool-result-pruner` | `ctx.toolResultPruner` |

## 三、一次 turn 的主闭环

```text
turn/start
  -> claim inbox messages
  -> assemble system prompt + tools
  -> agent/pre-step
  -> append user/message
  -> deriveMessages from session surface
  -> agent/request
  -> llm/stream
  -> assistant/chunk* / assistant/message
  -> tool/call* -> execute -> tool/result*
  -> next step if work remains
  -> agent/turn-stopping
  -> turn/end
```

`turn/*`、`step/*`、`user/*`、`assistant/*`、`tool/*` 是 durable session events；`agent/*`、`llm/stream`、`tools/*` 是 live extension points。

## 四、三种 context

不要把以下概念混为一谈：

1. **Cordis `ctx`**：插件之间共享的 runtime services 和事件。
2. **Agent runtime context**：Agent 的 `agent.ctx`、inbox、steering 和 injected messages。
3. **Model context**：system prompt、tool schema 和 `session.deriveMessages()` 最终形成的 LLM messages。

模型可见内容必须能从 Session Log 重建。新的模型可见输入不能只放在内存变量里。

## 五、最重要的架构判断

- Session Log 是事实来源，surface 是当前模型可见历史的投影。
- System Prompt 和消息历史分离，工具 schema 也由独立 registry 组装。
- Compaction 是 surface replacement，不是删除原始日志。
- Token meter 负责测量，模型 adapter 负责声明 context window。
- 能力通过 service definition/provider/consumer 三角色形成可替换 seam。
