# 主链路追踪

## 一次普通输入

| 顺序 | 代码位置 | 关键动作 |
| --- | --- | --- |
| 1 | `packages/core/agent-loop/src/agent.ts` | `send()` 将消息放进 inbox |
| 2 | 同文件 | `wakeDriver()` 启动 running phase |
| 3 | `turn()` | append `turn/start`，创建 step |
| 4 | `preStep()` | claim inbox、assemble prompt、运行 `agent/pre-step` |
| 5 | `turn()` | append `user/message`、`step/start` |
| 6 | `step()` | `deriveMessages()` 后调用 `buildRequest()` |
| 7 | `buildRequest()` | prepare adapter call，记录 `request/header` 和 `request/context` |
| 8 | `step()` | 消费 `llm.stream()`，记录 assistant chunks/message |
| 9 | `executeToolCalls()` | 工具调用和结果进入 next-step inbox |
| 10 | `turn()` | 没有后续工作时 append `turn/end` |

## 上下文在哪里改变

```text
inbox claim          动态输入被选中
preStep waterfall    插件可重写/拒绝本步输入
user/message append  模型可见输入被持久化
systemPrompt assemble 系统和工具上下文更新
deriveMessages      从当前 surface 重建历史
compaction replace  旧 surface 被新 checkpoint 替代
```

## 需要特别验证的边界

- `inject()` 不唤醒，`steer()` 会唤醒。
- 首个输入被拒绝时仍可能留下无 step 的 turn boundary。
- assistant chunk 用于流式回放，assistant message 是完成后的逻辑消息。
- tool result 可能追加 next-step，而不是立刻递归调用模型。
