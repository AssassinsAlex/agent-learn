# 运行时与插件系统

## 结论

DeepSeek Harness 的“核心”更像一棵 Cordis plugin tree，而不是一个固定的中央 orchestrator。配置层决定挂载哪些插件以及它们的顺序，事件和 service seam 决定插件如何协作。

## 三个层次

1. **Service Definition**：声明能力接口，例如 `ctx.llm`、`ctx.compaction`。
2. **Service Provider**：实现能力，例如 DeepSeek adapter、basic compaction backend。
3. **Consumer**：使用能力，例如 Agent Loop、human compact command、overflow handler。

## Profile / bundle / patch

启动时从空配置开始，依次叠加：

```text
profile bundles
  -> profile patch
  -> Harness home patch
  -> --patch overlay
```

patch 按 row id 替换整行配置，或插入新 row。因此插件不仅可注册代码，也能被上层配置替换。

## 为什么这种设计重要

- 可以替换模型 provider，而不改 Agent Loop。
- 可以替换文件系统或 sandbox provider，连带改变 Bash、PTY、LSP 的执行世界。
- 可以让一个 session 拥有独立的工具和 prompt 注册作用域。
- 插件卸载时，事件监听和注册项能够反向清理。
