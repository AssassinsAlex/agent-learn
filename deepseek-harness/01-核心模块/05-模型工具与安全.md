# 模型、工具与安全边界

## 模型层

`packages/llm/llm` 定义 message、stream chunk、BlockAssembler 和 adapter seam；`llm-deepseek` 提供 DeepSeek 相关路由和文件 API；`token-meter` 单独负责 pressure measurement。

模型层的职责是把 provider 差异收敛到统一的 `ctx.llm`，而不是让 Agent Loop 了解具体 HTTP API。

## 工具层

工具由 `ctx.tools` 做 scoped registration，并经过：

```text
tool/call
  -> tools/pre-execute
  -> tools/execute
  -> tools/post-execute
  -> tool/result
```

工具 schema 在 prompt assembly 阶段进入模型上下文，工具结果在 Session surface 中成为后续请求的一部分，也是 Compaction 的主要压力来源。

## 文件、进程与 sandbox

`fs`、`shell`、`subprocess`、`sandbox` 是 capability seams。替换 provider 可以把同一套 Bash、PTY 和 LSP consumer 移到远程或受限执行环境，而无需改工具业务逻辑。

## 学习重点

- tool schema 是否会被 request header 持久化？
- approval policy 在 `tools/pre-execute` 还是 provider 层生效？
- sandbox 是工具自身能力，还是 subprocess consumer 的包装层？
- tool result 的错误、超时和取消如何影响下一 step？
