# 学习路线

## 学习目标

理解 `pi-earendil` 这个具体版本如何把用户输入、模型调用、工具执行、会话状态和终端交互组织成一个可扩展且可恢复的 agent。

## 总分结构

```text
Pi agent
├── packages/coding-agent：CLI、AgentSession、会话、工具、扩展和交互/RPC/print 模式
├── packages/agent：通用 Agent runtime、agent loop、事件和状态管理
├── packages/ai：统一多 Provider LLM API、模型目录和流式协议
├── packages/tui：终端组件、输入、差分渲染和 Markdown
└── packages/storage：可选的持久化实现（如 sqlite-node）
```

## 建议顺序

1. **仓库与运行入口**：根 `package.json`、`packages/coding-agent/src/cli.ts`、`main.ts`，确认模式分流和 runtime 创建。
2. **AgentSession 外壳**：阅读 `core/agent-session.ts`，理解 coding-agent 如何持有上下文、模型、工具和事件监听器。
3. **通用 Agent loop**：阅读 `packages/agent/src/agent-loop.ts` 与 `agent.ts`，掌握 turn、tool batch、steering、follow-up 和停止条件。
4. **模型边界**：阅读 `packages/ai` 的核心类型、stream API 与 provider 实现，弄清 LLM 事件如何统一。
5. **工具执行**：阅读 `core/tools/*`、权限/trust、输出截断和并行执行路径。
6. **会话与上下文**：先理解树状 Session 的 entry、parentId、leaf、branch path，再阅读 JSONL/SQLite storage 与 branching 测试。
7. **Compaction 层**：掌握 token 阈值、cut point、split-turn、summary、retained tail，以及 compaction entry 如何重新进入 context。
8. **会话操作**：分别验证同一 session 的 `moveTo`/tree navigation 与 coding-agent 的 fork/new session，避免把两者混淆。
9. **交互与扩展**：阅读 interactive mode、TUI、RPC、extensions loader/runner 和事件总线。
10. **低风险实验**：先跑 offline/help/print，再验证一次对话、工具调用、恢复、分支切换、compaction 和取消。

## 横向比较亮点

在学习 Pi Session Tree 后，对照 `deepseek-harness` 的 append-only `SessionEvent` log 和 `codex-cli` 的 thread/rollout fork，重点比较“同一 session 内导航分支”和“复制出新 session”这两种不同设计。结论记录在[跨项目 Session 对比](跨项目Session对比.md)。

## 第一阶段交付物

- 仓库包地图
- CLI 到 `createAgentSessionRuntime` 的启动调用链
- `agentLoop` 的状态机和事件顺序
- 模型请求、工具结果、会话消息的三条数据流
- 每条结论对应源码路径和 commit

## 每个模块的固定问题

1. 输入来自哪里，输出交给谁？
2. 持有状态的对象是谁，状态何时改变？
3. 正常路径与错误/取消路径分别如何走？
4. 与哪些模块存在同步或异步边界？
5. 哪段源码或哪次实验可以证明上述结论？
