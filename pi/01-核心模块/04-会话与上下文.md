# 会话与上下文

## 先区分两套 Session

Pi 这个仓库里存在两套相似但不同的会话实现：

| 实现 | 文件 | 使用者 | 定位 |
| --- | --- | --- | --- |
| coding-agent `SessionManager` | `packages/coding-agent/src/core/session-manager.ts` | `AgentSession`、CLI、interactive/print/RPC | Pi coding agent 的实际持久化、恢复、分支和 JSONL 管理 |
| agent-core Harness `Session` | `packages/agent/src/harness/session/session.ts` | 通用 `AgentHarness` | 可嵌入的通用 session/storage 抽象，支持 memory/JSONL backend |

两者都使用 entry、`parentId`、leaf 和 context projection 这类树状思想，但不是同一个类，也不存在 `AgentSession extends Session` 或 `SessionManager extends Agent` 的继承关系。

实际 coding-agent 关系是：

```text
AgentSession
  ├── 持有 Agent（来自 pi-agent-core）
  └── 持有 SessionManager（coding-agent 自己的 session 实现）
```

通用 Harness 则是：

```text
AgentHarness
  ├── 持有通用 Session
  └── 调用 agentLoop（而不是持有 coding-agent AgentSession）
```

## 关注点

- 消息的数据结构、角色和元数据
- system prompt、用户输入、工具定义的拼装
- 上下文长度控制、裁剪与压缩
- 会话持久化、恢复、分支与导出
